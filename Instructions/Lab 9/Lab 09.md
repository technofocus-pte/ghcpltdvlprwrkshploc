**ラボ 09: プロジェクトに継続的インテグレーション (CI)
を使用するワークフローを作成する**

目標：

高品質の基準を維持することが重要なソフトウェア
プロジェクトに取り組んでいると想像してください。コードが堅牢でエラーがないようにするために、GitHub
Actions を使用して継続的インテグレーション (CI)
を実装することにしました。CI
は、コードベースに変更が加えられるたびにテストを実行し、コード品質をチェックするプロセスを自動化するのに役立ちます。CI
ワークフローを作成することで、Markdown
ファイルを自動的にリントし、テストを実行し、コード品質に関するフィードバックを即座に受け取ることができ、プロジェクトが一貫して品質基準を満たしていることを確認できます。

このハンズオンラボでは、次のことを行います:

- テストワークフローを作成する: Markdown
  ファイルをリントし、フォーマットの問題をチェックするために特別に設計された
  GitHub Actions ワークフローを設定します。

- ワークフローの構成と更新: ワークフロー
  ファイルの構成を練習して、自動リンティングに必要なジョブと手順を定義し、必要に応じて更新して機能を強化します。

- プルリクエストの作成: プルリクエストを作成して変更を統合し、CI
  ワークフローをテストし、品質チェックがどのように自動化されるかを観察できるようにします。

- CI
  ワークフローの結果を分析して、問題を報告し、コード品質を保証する方法を理解します。
